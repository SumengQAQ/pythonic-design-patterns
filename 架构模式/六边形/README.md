# 六边形架构（Hexagonal Architecture / Ports & Adapters）🏗️

## 这玩意儿是啥？

六边形架构 = **让你的核心业务代码不受框架/数据库/UI 影响**。

```
┌───────────────────────────────────────────────────┐
│                   外层（适配器）                  │
│  ┌───────────┐  ┌────────────┐  ┌──────────────┐  │
│  │   MySQL   │  │    内存    │  │   CLI终端    │  │
│  │ Repository│  │ Repository │  │    View      │  │
│  └────┬──────┘  └──────┬─────┘  └──────┬───────┘  │
│       │                │               │          │
├───────┴────────────────┴───────────────┴──────────┤
│              边界（Ports 接口）                   │
│  ┌───────────────────────────────────────────────┐│
│  │             内层（核心业务）                  ││
│  │                                               ││
│  │  · 领域模型（Model）— 纯数据，零依赖          ││
│  │  · 业务服务（Service）— 只依赖接口，不依赖实现││
│  │  · 端口（Ports）— 接口定义，契约              ││
│  └───────────────────────────────────────────────┘│
└───────────────────────────────────────────────────┘
```

## 核心原则：依赖反转

> **核心层不依赖外层，外层依赖核心层。**

这意味着：

- 你的业务代码不知道 MySQL 存在
- 你的业务代码不知道 `input()` / `print()` 存在
- 换数据库 = 写个新 Adapter，核心代码一行不改
- 加 GUI 界面 = 写个新 View，核心代码一行不改

## 和 MVC/MVP/MVVM 的区别

| 架构       | 关注点                 | 核心思想                |
| ---------- | ---------------------- | ----------------------- |
| MVC        | 三层职责分离           | Model-View-Controller   |
| MVP        | View 和 Model 完全解耦 | Presenter 中介          |
| MVVM       | 数据绑定               | ViewModel 自动同步 View |
| **六边形** | **核心与基础设施解耦** | **Ports & Adapters**    |

六边形是更高层的架构模式，可以和 MVC/MVP/MVVM 共存。
